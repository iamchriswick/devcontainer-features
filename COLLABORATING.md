# Collaborating

How to work on this repository: a collection of Dev Container Features under `src/`, each with its tests under `test/`.

## Spec, ticket and PR flow

1. A spec is one GitHub issue. A spec split into parts has one sub-issue per part.
2. Tickets are sub-issues of the spec, created in dependency order and marked "blocked by" the tickets they depend on. A ticket that needs a human gets the `hitl` label.
3. Each ticket lists acceptance criteria as checkboxes. Tick a box only when that criterion holds.
4. One Feature gets one branch and one PR. The PR description lists `Closes #<ticket>` for every ticket it completes, so the tickets close when the PR is merged.

## Branch naming

Branch names follow [Conventional Branch](https://conventional-branch.github.io/). Cut the branch from `main`.

```text
feat/<feature-id>
```

For example: `feat/claude-code-persistent`.

A Feature branch changes only `src/<feature-id>/` and `test/<feature-id>/`. Changes to `.claude/` and `CLAUDE.md` go on `ai/claude-<description>` branches, never into a Feature's PR.

## Commit format

Commits follow [Conventional Commits](https://www.conventionalcommits.org/). The scope is the Feature id, and the subject ends with the ticket reference.

```text
<type>(<feature-id>): <summary> (#<ticket>)
```

For example: `fix(claude-code-persistent): remove persisted credentials when CCP_CRED is off (#6)`.

## Feature file layout

```text
src/<feature-id>/
├── devcontainer-feature.json   # "id" equals <feature-id>; "version" is semver
├── install.sh                  # entrypoint, runs as root at image build; must be executable
├── NOTES.md                    # merged into the generated README.md
└── ...                         # any other files the Feature ships

test/<feature-id>/
├── scenarios.json              # each key is a scenario, each value a devcontainer.json
└── <scenario>.sh               # one script per scenario, named after it
```

- Don't edit `src/<feature-id>/README.md`. The release workflow generates it from `devcontainer-feature.json` and `NOTES.md`.
- Each scenario script sources `dev-container-features-test-lib`, runs `check "<label>" <command>` for each assertion, and ends with `reportResults`.

Run a Feature's scenarios from the repository root:

```bash
devcontainer features test -f <feature-id> --skip-autogenerated .
```

### Global tests

`test/_global/` holds scenarios that are not tied to a single Feature, such as several Features installed together. It uses the same layout: `scenarios.json` plus one script per scenario, named after it.

```text
test/_global/
├── scenarios.json
└── <scenario>.sh
```

Run them from the repository root:

```bash
devcontainer features test --global-scenarios-only .
```
